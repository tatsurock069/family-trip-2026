# family-trip-2026

2026年8月3日〜4日の関家8人による、天橋立・伊根・美山旅行用Webアプリです。
iPhone Safariと「ホーム画面に追加」からの利用を最優先にしています。

公開URL: https://tatsurock069.github.io/family-trip-2026/

## iPhoneでの使い方

1. 公開URLをSafariで開く
2. 画面下の共有ボタンをタップ
3. `ホーム画面に追加` → `追加`
4. ホーム画面の「関家の旅」アイコンから起動

一度オンラインで最後まで読み込めば、圏外でも旅程・買い出し・BBQ・その他の主要画面を表示できます。チェック状態、選択中のプラン、任意予算項目はiPhone内に自動保存されます。

## 主な機能

- 初日プランA/B切替（予算・次の予定・撮影項目と連動）
- 次の予定（次の行き先の地図を直接表示）とDay1／Day2見どころカルーセルをまとめたホーム
- 6施設の観光地紹介（公式情報・Google Maps・旅程からの直リンク）
- Day1／Day2の折りたたみ旅程（8月4日はDay2を自動展開）
- 住所、移動目安、Google Mapsへの案内、ヴィラの鍵受取・チェックイン情報
- 費用シミュレーターと実支出入力（残額・1人あたり表示）
- ロピア買い出しチェック（未購入のみ表示・カテゴリ一括／個別折りたたみ・数量変更・項目追加・カテゴリ別進捗）
- BBQコースのお品書き、12品へのクイックジャンプ、食材別火加減、簡易タイマー
- 構図・画角・優先度つきのAロール／Bロール／環境音チェックリスト
- 撮影カテゴリ折りたたみ、未撮影・必須フィルター、ベストテイク・撮り直し記録
- 5カテゴリ・全75個の協力型ミッションと、5個ごとの16段階ランク
- 持ち物チェック
- localStorageによる端末内保存
- PWA／オフライン表示
- 画面ごとのスクロール位置保存、再タップ／TOPボタンによる上部復帰

## ミッション端末の使い分け

初回に `管理者 / 優典 / 綾菜 / 慶典 / 杏菜 / 波瑠菜` から、そのiPhoneを使う人を選びます。記録は自動で外部へ送信・同期されず、それぞれの端末内に保存されます。

- `管理者`: 5人の公式記録を切り替えて管理します。複数人で達成したときは「複数人にまとめて記録」を使えます。
- `優典（中2）`: 判断、段取り、年下のサポートを含む内容です。
- `綾菜（小6）`: 観察、撮影、家族への声かけを含む内容です。
- `慶典（小3）`: 探索、発見、安全にできるお手伝いを中心にしています。
- `杏菜（年長）`: ひらがな中心で、自分で挑戦できる短い内容です。
- `波瑠菜（年少）`: 指さす、聞く、まねする内容を中心にした閲覧用の「おとなといっしょ」画面です。誤操作防止のため本人画面では達成操作ができません。達成記録は管理者が代行します。

最終結果は親の `管理者` を正とします。本人端末では結果画面を親に見せ、管理者端末へ反映します。端末の利用者を変える場合は、ミッション画面上部の「端末設定」から変更できます。以前の `自分用 / 幼児 / 家族管理` 設定は新しい名前別モードへ自動移行し、5人分の達成記録もそのまま引き継がれます。

ランクはXPではなく達成ミッション数で決まり、5個達成するごとに1段階上がります。XPは副スコアとして残ります。兄弟間の順位やランキングは表示せず、それぞれの次のランクまでの進捗だけを表示します。

## ファイル構成

- `index.html`: 画面構造と旅行データ
- `assets/css/style.css`: iPhone優先のレイアウトと見た目
- `assets/js/app.js`: 画面切替、保存、予算、進捗、タイマー
- `manifest.webmanifest`: ホーム画面追加設定
- `sw.js`: オフラインキャッシュと更新制御
- `assets/icons/`: ホーム画面・PWAアイコン
- `assets/images/`: アプリ用の生成イメージ写真

下部ナビは `ホーム / 旅程 / BBQ / 撮影 / ミッション / お道具箱` の6つです。買い出し、予算・支出、持ち物はホームまたは「お道具箱」から開きます。

外部ライブラリ、APIキー、外部データ送信は使用していません。

## 更新・公開方法

1. 対象ファイルを編集する
2. ローカル確認: リポジトリ直下で `python3 -m http.server 8000`
3. `http://localhost:8000/` を開いて主要機能を確認する
4. Service Workerの `CACHE` バージョンを、キャッシュ対象や重要な内容を変えた場合に更新する
5. 変更をコミットして `main` へpushする
6. GitHubの `Settings` → `Pages` が `main` / `/ (root)` になっていることを確認する
7. GitHub Pagesの公開URLで反映を確認する

Service WorkerはHTMLをネットワーク優先、同一オリジンの静的ファイルをキャッシュ優先＋バックグラウンド更新で扱います。新しいService Workerへ切り替わるとページが一度だけ自動再読み込みされます。

## 写真について

`assets/images/` の写真はアプリの雰囲気づくりのために生成したイメージです。特定施設や特定地点の正確な現況写真ではありません。住所・営業時間は各公式情報を確認して更新してください。

## 更新が見えないとき

Safariでページを開き直してください。それでも古い場合は、ホーム画面のアプリを終了してSafariで公開URLを再読み込みします。チェック状態はWebサイトデータを消さない限り保持されます。
